# Дизайн админки: как делаем

Решено 29.08.2026. Документ ведущий: спорные места правим здесь, а потом в коде,
не наоборот.

Админка — **отдельный продукт**. Она не витрина сети, а рабочий инструмент
сотрудника. Ни цвета, ни размеры, ни шрифты мобильного приложения сюда не
приходят. Единственное, что берётся из `@mr/tenants`, — название сети и логотип
в углу рельса.

## Что уже выбрано

| Решение | Значение |
| --- | --- |
| Палитра | «Камень»: тёплая нейтраль stone + тёмно-синий акцент |
| Тема | Светлая основная, тёмная закладывается переменными и включается позже |
| Сайдбар | Вариант Б: рельс 54 px + панель 194 px |
| Экран «Заказы» | Доска по статусам, таблица второй вкладкой |
| Шрифты | Inter для интерфейса, JetBrains Mono для цифр и кодов |

---

## 1. Принципы

1. **Поверхности почти монохромные.** Иерархию держат вес шрифта, отступ и
   тонкая линия. Заливки цветом — только у акцентной кнопки и активного пункта.
2. **Цвет означает смысл.** Зелёный, жёлтый, красный принадлежат состоянию:
   выполнено, ждёт, сломалось. Ими нельзя украшать.
3. **Плотность важнее воздуха.** Это экран, за которым сидят смену. Строка
   таблицы 36 px, а не 56. Плотность переключается пользователем.
4. **Сводка раньше подробностей.** Наверху экрана — что требует действия
   сегодня. Ниже — данные.
5. **Одно очевидное действие в строке.** Остальные прячутся под «…».
6. **Модалка — крайний случай.** Подробности открываются панелью справа,
   контекст не теряется.

## 2. Цвет

### 2.1 Светлая тема — источник правды

```css
:root {
  /* Поверхности */
  --bg:            #FAFAF9;  /* фон страницы */
  --surface:       #FFFFFF;  /* карточки, таблицы, сайдбар */
  --sunken:        #F5F5F4;  /* шапка таблицы, вложенные блоки, рельс */

  /* Текст */
  --ink:           #1C1917;  /* основной */
  --ink-2:         #57534E;  /* вторичный: подписи, неактивные пункты */
  --ink-3:         #A8A29E;  /* третичный: метки, плейсхолдеры, «—» */
  --on-acc:        #FFFFFF;  /* текст на акцентной заливке */

  /* Линии */
  --line:          #E7E5E4;  /* границы карточек и строк */
  --line-2:        #D6D3D1;  /* границы полей и вторичных кнопок */

  /* Акцент */
  --acc:           #1E3A8A;
  --acc-hover:     #1E40AF;
  --acc-sub:       #EEF3FF;  /* подложка активного пункта, выделенной строки */

  /* Состояния */
  --ok:            #15803D;  --ok-sub:   #F1F9F3;
  --warn:          #B45309;  --warn-sub: #FDF6EC;
  --bad:           #B91C1C;  --bad-sub:  #FDF1F1;

  /* Служебное */
  --skeleton:      #EFEDEC;
  --scrim:         rgba(28, 25, 23, .45);
  --focus:         #1E3A8A;
}
```

### 2.2 Тёмная тема — задел

Пишем сразу, включаем позже. Переменные те же, значения другие; ни один
компонент от этого не меняется.

```css
:root[data-theme="dark"] {
  --bg:       #0C0A09;  --surface: #1C1917;  --sunken:  #121110;
  --ink:      #FAFAF9;  --ink-2:   #A8A29E;  --ink-3:   #78716C;
  --on-acc:   #0C0A09;
  --line:     #292524;  --line-2:  #44403C;
  --acc:      #60A5FA;  --acc-hover: #93C5FD; --acc-sub: #172554;
  --ok:       #4ADE80;  --ok-sub:   #0A2412;
  --warn:     #FBBF24;  --warn-sub: #2A1E06;
  --bad:      #F87171;  --bad-sub:  #2B0E0E;
  --skeleton: #26221F;  --scrim: rgba(0,0,0,.6);  --focus: #60A5FA;
}
```

### 2.3 Правила применения

- Цвет в компоненте берётся **только** из переменной. Хекса в JSX и в классах
  Tailwind быть не должно.
- Тёмно-синий акцент — на одну кнопку в блоке. Если акцентных кнопок две, одна
  из них не акцентная.
- `--ok` / `--warn` / `--bad` не используются как декор. Зелёная рамка вокруг
  карточки просто потому что красиво — ошибка.
- Подложки `*-sub` только под текст того же семейства: `--bad` на `--bad-sub`.

### 2.4 Статусы заказа

| Статус в API | Подпись | Цвет | Смысл |
| --- | --- | --- | --- |
| `created`, `paid` | Оформлен, Оплачен | `--ink-3` нейтральный | ещё не в работе |
| `accepted` | Принят | `--acc` | взят в работу |
| `cooking` | Готовится | `--warn` | идёт время |
| `ready` | Готов | `--acc` | **ждёт действия** |
| `delivering` | В пути | `--warn` | идёт время |
| `completed` | Выполнен | `--ok` | закрыт |
| `cancelled` | Отменён | `--bad` | закрыт неудачей |

Просрочка — отдельный слой поверх любого статуса: левая полоса `--bad` 3 px у
строки и рамка `--bad` у карточки на доске. Порог берём из настроек ресторана,
не из кода.

### 2.5 Статусы брони

`requested` → `--warn` (ждёт ответа) · `confirmed` → `--ok` · `seated` → `--acc`
· `completed` → нейтральный · `cancelled`, `no_show` → `--bad`.

### 2.6 Цвета зон на карте

Различимы между собой, не из палитры бренда, читаются поверх карты при
заливке 18 %:

```
#1E3A8A  #0F766E  #B45309  #7E22CE  #B91C1C  #3F6212  #C2410C  #0369A1
```

## 3. Шрифты

### 3.1 Выбор

**Inter** — весь интерфейс. Причины конкретные: настоящие табличные цифры
(`tabular-nums`), разборчивость на 12–13 px, полная кириллица, вариативность —
один файл вместо четырёх начертаний.

**JetBrains Mono** — номера заказов, идентификаторы, коды iiko, ключи, хексы,
время в лентах событий. Всё, что сравнивают глазами по столбцу.

**Comfortaa в админке не используется.** Округлый дисплейный шрифт вредит
плотным таблицам: на 13 px он теряет различимость, а цифры в нём разной ширины.
Он остаётся мобильному приложению.

> Альтернатива, если захочется больше характера: **Golos Text** (Paratype,
> кириллица первого сорта, есть в Google Fonts). Решение обратимо — меняется
> одна строка в `@theme`.

### 3.2 Подключение

```html
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Inter:wght@400..700&family=JetBrains+Mono:wght@400;500;600&display=swap">
```

```css
--font-ui:   "Inter", ui-sans-serif, -apple-system, "Segoe UI", Roboto, sans-serif;
--font-mono: "JetBrains Mono", ui-monospace, SFMono-Regular, Menlo, monospace;
```

Отдельным пунктом: **сейчас в админке не подключён ни один шрифт** — в коде
стоит `'Comfortaa'` и `'Onest'`, а в `index.html` ссылок нет, и всё рендерится
системным. Это чинится первым шагом.

### 3.3 Шкала

| Ключ | Размер / интерлиньяж | Где |
| --- | --- | --- |
| `xs` | 11 / 16 | капслок-метки, счётчики, заголовки групп |
| `sm` | 12 / 18 | вторичная строка в таблице, подписи полей |
| `base` | 13 / 20 | **плотный UI**: таблицы, поля, пункты меню |
| `md` | 14 / 22 | основной текст, кнопки, карточки |
| `lg` | 15 / 22 | подзаголовки блоков |
| `xl` | 17 / 24 | заголовок раздела в шапке |
| `2xl` | 20 / 28 | заголовок модалки и карточки заказа |
| `3xl` | 24 / 32 | числа в сводке |

Начертания: **400** текст, **500** акцент внутри строки, **600** заголовки и
кнопки, **700** числа в сводке. Никаких 300, 800 и 900.

Трекинг: `-0.01em` от 17 px, `-0.02em` от 24 px. Капслок-метки `+0.08em`.

Цифры: `font-variant-numeric: tabular-nums` **обязательно** для всех сумм,
счётчиков и колонок с числами — иначе при обновлении строка дёргается.

## 4. Размеры

Своя шкала, мобильные токены не импортируем. У `@mr/design-tokens` радиус 22 px
и тени, заданные RN-свойствами (`shadowOpacity`), — в вебе они не работают
вовсе, а размеры рассчитаны на палец.

### 4.1 Отступы

Шаг 4, без исключений: `0, 2, 4, 6, 8, 10, 12, 16, 20, 24, 32, 40, 48, 64`.

Рабочие значения: внутри карточки 12–16, между карточками 10, поля рабочей
области 20, между блоками 16, между секциями 24.

### 4.2 Скругления

| Ключ | px | Где |
| --- | --- | --- |
| `sm` | 4 | бейджи статусов, мелкие метки |
| `md` | 6 | кнопки, поля ввода, чипы фильтров |
| `lg` | 8 | карточки, блоки таблиц, карточки доски |
| `xl` | 10 | панели, выдвижной ящик, поповеры |
| `2xl` | 12 | модальные окна |
| `full` | 999 | аватар, счётчики-пилюли |

### 4.3 Линии и тени

Граница везде **1 px** `--line`. Двухпиксельными бывают только фокус и полоса
активного пункта.

```css
--sh-1: 0 1px 2px rgba(28,25,23,.05);                                        /* карточка */
--sh-2: 0 1px 2px rgba(28,25,23,.04), 0 2px 8px -2px rgba(28,25,23,.08);     /* дропдаун, поповер */
--sh-3: 0 4px 12px -4px rgba(28,25,23,.12), 0 16px 40px -12px rgba(28,25,23,.18); /* модалка, панель */
```

### 4.4 Высоты

| Элемент | px |
| --- | --- |
| Шапка рабочей области | 56 |
| Шапка таблицы | 34 |
| Строка таблицы — компактно / обычно | 36 / 44 |
| Кнопка — xs / sm / md / lg | 28 / 32 / 36 / 40 |
| Поле ввода, селект | 36 |
| Пункт сайдбара | 32 |
| Иконка в интерфейсе / в рельсе | 16 / 18 |
| Аватар — в списке / в подвале | 24 / 28 |

Минимальная цель мыши — **28 px**, не 44. Правило 44 px из мобильного гайда
сюда не переносится: здесь курсор, а не палец.

### 4.5 Плотность

Два режима, переключатель в шапке таблицы: **Компактно** (36) и **Обычно** (44).
Выбор хранится в `localStorage` и общий для всех таблиц.

## 5. Сетка и адаптация

### 5.1 Ширины

- Рабочая область — **на всю ширину окна**, без потолка. Потолок 1100 px в
  нынешней админке жмёт таблицу заказов в треть монитора.
- Формы, тексты, описания — не шире **720 px**.
- Строка читаемого текста — 65–75 символов.

### 5.2 Точки перелома

| Ширина | Поведение |
| --- | --- |
| `≥1600` | Доска показывает 5 колонок. Панель заказа 420 px закреплена справа, не перекрывает. |
| `1280–1599` | База. Панель заказа выдвигается поверх, 420 px. |
| `1024–1279` | Панель сайдбара сворачивается в рельс кнопкой. Таблица прячет колонки «Ожидание» и «Состав». |
| `768–1023` | Только рельс. Доска скроллится горизонтально. Панель заказа — на весь экран. |
| `<768` | Рельс становится нижней панелью на 5 иконок. Доступны «Заказы» и «Брони», остальное — экран «Раздел открывается на компьютере». |

Админку не делаем полноценно мобильной: это не тот инструмент. Но «принять
заказ с телефона» работать обязано.

## 6. Сайдбар (вариант Б)

```
┌──────┬──────────────────┐
│ 54px │      194px       │   вместе 248
│ рельс│      панель      │
└──────┴──────────────────┘
```

**Рельс** — фон `--sunken`, граница справа `--line`.
Сверху логотип тенанта 30×30, радиус 8. Ниже пять разделов, иконка 18 в
квадрате 36×36 радиуса 9. Активный — заливка `--acc`, иконка `--on-acc`.
Точка-индикатор 6 px `--bad` в правом верхнем углу, если внутри раздела есть
что чинить (несопоставленные позиции кассы, упавшие заказы).

Разделы рельса: **Операции · Меню · Маркетинг · Сеть · Система**.

**Панель** — фон `--surface`.
Сверху название раздела 15/600 и подпись 11 `--ink-3` («смена 29 августа»).
Пункты высотой 32: иконка 16 + текст 13. Активный — фон `--acc-sub`, текст
`--acc`, полоса 2 px слева.

Счётчик справа появляется, **только если там ждут действия**: заказы, брони,
неотвеченные отзывы, ошибки кассы. «214 блюд» — не новость, счётчика нет.
Счётчик проблемы — пилюля `--bad` на `--bad-sub`.

Ниже разделителя блок **«Быстрый доступ»**: до трёх пунктов из других разделов,
закреплённых пользователем. Хранится в `localStorage`.

Подвал — аватар, имя, роль; по клику меню: профиль, тема, выход.

Панель сворачивается кнопкой (горячая клавиша `[`), остаётся один рельс.
Состояние — в `localStorage`.

Поиск живёт не в сайдбаре, а на `⌘K`: разделы, заказ по номеру, гость по
телефону, блюдо по названию.

## 7. Шаблоны рабочей области

Доска — это шаблон **одного** экрана. Всего шаблонов девять, каждый раздел
получает свой.

**Ш1 · Доска по статусам.** Колонки на статус, карточки переносятся мышью.
Шапка колонки: подпись, число, цветная полоса статуса. Сверху сводка полосой и
блок тревоги, если что-то просрочено.

**Ш2 · Расписание дня.** Сетка «время × стол», брони прямоугольниками. Слева
шкала часов, сверху столы. Клик по пустому месту — новая бронь.

**Ш3 · Таблица.** Фильтры-чипы, сортировка по клику в шапку, серверная
пагинация, переключатель плотности, выгрузка. Поиск — на сервере, не фильтром
по загруженному списку.

**Ш4 · Список и карточка.** Слева узкий список 268 px, справа объект целиком.
Без модалок.

**Ш5 · Дерево и редактор.** Слева дерево категорий, в центре список позиций,
справа редактор выбранной. Сохранение по месту.

**Ш6 · Галерея карточек.** Сетка карточек с картинкой, порядок меняется
перетаскиванием. Для того, у чего есть внешний вид.

**Ш7 · Конструктор шагов.** Цепочка шагов сверху вниз, у каждого условие и
задержка. Справа предпросмотр того, что увидит гость.

**Ш8 · Карта и панель.** Карта на всю площадь, слева список объектов, рисование
поверх.

**Ш9 · Сопоставление.** Две колонки: слева несопоставленное, справа кандидаты с
серверным поиском. Кнопка «связать» между ними, счётчик остатка сверху.

### Раздел → шаблон

| Раздел | Шаблон | Примечание |
| --- | --- | --- |
| Заказы | **Ш1 Доска** + Ш3 Таблица вкладкой | Карточка заказа выдвигается панелью из обоих видов |
| Брони | **Ш2 Расписание** + Ш3 Таблица вкладкой | Панель брони так же |
| Отзывы | **Ш4 Список и карточка** | Ответ пишется справа, не в модалке |
| Блюда и меню | **Ш5 Дерево и редактор** | Категории → блюда → карточка блюда |
| Добавки | **Ш3 Таблица** | Редактор панелью |
| Акции | **Ш6 Галерея** | У акции есть картинка, таблица её убивает |
| Промокоды | **Ш3 Таблица** | Форма панелью |
| Уведомления | **Ш7 Конструктор** | Список кампаний → шаги цепочки |
| Гости | **Ш3 Таблица** с серверным поиском | Карточка гостя панелью: баллы, уровень, история |
| Рестораны | **Ш4 Список и карточка** | Много полей: адрес, часы, телефоны, зоны |
| Зоны доставки | **Ш8 Карта и панель** | Leaflet остаётся |
| Касса iiko | **Ш9 Сопоставление** + вкладки | Самый тяжёлый экран, переносим последним |
| Обновление | **Панель состояния** | Карточки синхронизаций со статусом и кнопкой |

## 8. Компоненты

**Кнопка.** Три вида: `primary` (заливка `--acc`), `ghost` (фон `--surface`,
граница `--line-2`), `quiet` (без фона и границы). Опасное действие — `quiet`
с текстом `--bad`; красных заливок в интерфейсе нет, кроме подтверждения
удаления в модалке. Размеры из §4.4, радиус 6.

**Поле ввода.** Высота 36, радиус 6, граница `--line-2`, фон `--surface`.
Фокус — граница `--acc` и кольцо 2 px `--acc-sub`. Ошибка — граница `--bad` и
текст ошибки 12 px под полем: что не так и что сделать.

**Бейдж статуса.** Радиус 4, размер 11/600, точка 5 px слева, подложка `*-sub`,
текст цветом состояния. Статус читается формой и цветом до чтения текста.

**Таблица.** Шапка — `--sunken`, метки моноширинные 10,5 капслоком `--ink-3`.
Строки разделены `--line`, у последней разделителя нет. Числа справа и
`tabular-nums`. Наведение — фон `--sunken`. Выбранная строка — `--acc-sub`.
Одно основное действие в строке кнопкой, остальные под «…».

**Доска.** Колонка минимум 200 px, карточка радиуса 8 с границей `--line`.
Перетаскивание — `dnd-kit`, при переносе статус уходит на сервер сразу,
откат при ошибке. Пустая колонка показывает пунктирную рамку.

**Панель подробностей.** Ширина 420, выезжает справа, `--sh-3`, закрывается по
`Esc` и по клику вне. При ширине ≥1600 закреплена и не перекрывает список.

**Модалка.** Только для необратимого: удаление, отмена заказа, ручное изменение
баланса баллов. Радиус 12, ширина по содержимому до 520. Правило про
`statusBarTranslucent` из мобильного гайда сюда **не относится** — это веб.

**Тост.** Правый нижний угол, 4 секунды, с кнопкой «Отменить» там, где отмена
возможна. Успех не требует тоста, если результат виден на экране.

## 9. Состояния экрана

| Состояние | Как выглядит |
| --- | --- |
| Загрузка | Скелетоны формой контента, цвет `--skeleton`. Никаких спиннеров по центру пустого экрана. |
| Пусто впервые | Заголовок, объяснение в одну строку, кнопка первого действия. |
| Пусто после фильтра | «По этим условиям ничего нет» и кнопка «Сбросить фильтры». |
| Ошибка | Что случилось и что сделать. Кнопка «Повторить». Технический текст — под катом. |
| Нет прав | Раздел не показывается в сайдбаре вовсе. |

Тексты — на русском, к сотруднику на «вы», без извинений. Кнопка называет
действие: «Опубликовать», после — тост «Опубликовано».

## 10. Движение

Длительности: **120 мс** отклик на нажатие, **160 мс** появление поповера и
тоста, **200 мс** выезд панели. Кривая `cubic-bezier(.2, 0, 0, 1)`.

Ничего не анимируем дольше 200 мс. Обновление данных в таблице происходит без
анимации — мигание строк мешает читать.

`@media (prefers-reduced-motion: reduce)` отключает переходы везде.

## 11. Доступность

- Контраст текста к фону не ниже **4.5:1**, у крупного — 3:1. Пары из §2
  проверены.
- Фокус виден всегда: кольцо 2 px `--focus` с отступом 2 px. `outline: none`
  без замены запрещён.
- Полная работа с клавиатуры: `Tab` по элементам, `⌘K` поиск, `[` сайдбар,
  `Esc` закрывает панель и модалку, стрелки двигают по строкам таблицы.
- Статус никогда не передаётся одним цветом — рядом всегда текст.

## 13. Правила

- **Не импортировать `@mr/design-tokens`.** Размеры оттуда мобильные, тени не
  работают в вебе. У админки своя шкала — §4.
- **Не брать цвета из `@mr/tenants`.** Исключение одно: логотип в рельсе.
- **Инлайн-стилей нет.** Сейчас весь интерфейс собран ими — 8 274 строки кода
  и ни одного CSS-файла. В новом коде только классы Tailwind и переменные.
- **Хексов в компонентах нет.** Цвет приходит переменной.
- **Деньги — целые копейки `int`.** Форматирование одной функцией из
  `lib/format.ts`, всегда с `tabular-nums`.
- **Даты из API — UTC.** Показываем в тайзоне ресторана из конфига тенанта.
- **У каждого раздела свой адрес.** Состояние вкладки в `useState` — то, из-за
  чего сейчас не работают «назад» и обновление страницы.
- **Тёмная тема пишется сразу** переменными, даже пока выключена. Дописывать её
  потом дороже.

## 14. Порядок работ

1. **Каркас.** Tailwind v4 и shadcn/ui в существующий Vite, переменные из §2,
   шрифты из §3, TanStack Router с адресом на каждый раздел. Старые вкладки на
   это время продолжают работать.
2. **Сайдбар Б.** Рельс, панель, `⌘K`, сворачивание, «Быстрый доступ».
3. **Заказы доской.** Шаблон Ш1 целиком: колонки, перетаскивание, сводка,
   тревога о просрочке, панель заказа справа.
4. **Заказы таблицей.** Ш3 на тех же данных, второй вкладкой. Здесь же
   появляется общий табличный компонент для всех остальных разделов.
5. **Остальные разделы** по таблице из §7, по одному. Простые — «Промокоды»,
   «Добавки», «Гости» — идут первыми и обкатывают Ш3.
6. **Касса и зоны последними**, когда набор компонентов устоялся: `IikoTab` на
   1 249 строк и карта — самое дорогое.

Проверка на каждом шаге: `npx tsc --noEmit` и сборка бандла.
